# 🎓 XMU-skill

> **论文格式一把梭：把你的论文 .docx 一键调成厦大经院要求的格式。**

写论文已经够累了，谁还想对着《格式规范》一条条数页边距、抠字号、调行距、数页码？🫠

这个 skill 专门干这件事——你把 `.docx` 丢进来，它按厦门大学（经济学院）的规范把**页面、样式、段落、编号、页码、页眉、封面**整套对齐，还能顺手把封面校徽换成你学校的官方标志。

```
📄 论文.docx  ➜  🔍 体检  ➜  🛠️ 修复  ➜  📑 页眉页脚  ➜  🎨 换校徽  ➜  ✅ 复核  ➜  🎓 论文-交付.docx
```

---

## ✨ 它能做什么

| 能力 | 说明 |
|---|---|
| 📐 **页面与分节** | A4 纸张、规范页边距、文档网格；页码「封面无码 → 前置罗马数字 → 正文阿拉伯重新起 1」 |
| 🎨 **样式表** | 按**样式名**（不是内部 styleId）把规范样式同步进你的文档，缺了就注入 |
| 📝 **段落角色** | 章/节/小节标题、图表题、参考文献……按语义角色自动套样式，并清掉和规范打架的直接格式 |
| 🔢 **编号归一** | 剥掉标题里手写的「1.1」「第一章」，改由自动编号生成——不然会渲染出「1.1 1.1 选题背景」这种鬼东西 |
| 📑 **页眉页脚** | 三节式重建：封面无页码 → 前置罗马数字 → 正文阿拉伯；奇数页页眉自动跟章名（`STYLEREF` 域），偶数页放论文题目 |
| 🏫 **换学校** | 封面校徽/校名图换成指定学校的官方标志，页眉校名一起改 |
| 🩺 **只体检不改** | 也可以只出一份格式偏差报告，一个字都不动 |

> **只吃 `.docx`**。Word 97-2003 的老 `.doc` 请先用 Word 另存为 `.docx`（脚本 `doc2docx.py` 也能代劳，无损保留分节、页眉页脚、表格）。

## 📦 安装

把 `thesis-format-conformer` 目录整个放进 skill 目录，然后在对话里说「按厦大格式调整我的论文」之类的话，它就会自己接上。

```
XMU-skill/
├── README.md                    # 你正在看的这份
├── LICENSE                      # MIT
└── thesis-format-conformer/     ← 把它作为 skill 导入
    ├── SKILL.md                 # skill 说明书（给 agent 看的）
    ├── README.md                # 子目录速查版（给人看的）
    ├── assets/                  # 规范样式库 / 编号库 / 校徽
    ├── references/              # 格式规范全文
    └── scripts/                 # 干活的全在这
```

### 依赖

```bash
pip install lxml pillow
```

- `lxml` —— 解析 OOXML（**必需**）
- `pillow` —— 仅换封面校徽时需要（`fmt_cover.py`）
- `pywin32` —— 仅 `.doc → .docx` 时需要，且**必须装了 Microsoft Word**（`doc2docx.py`）

## 🚀 五步走

### 第 1 步 · 体检（只读，不改文件）🔍

```bash
python scripts/fmt_check.py "我的论文.docx" --json 报告.json
```

输出六节报告：页面与分节 / 样式表 / 段落角色分布 / 段落格式偏差明细 / 页眉页脚 / **标题编号冲突**。

每一处偏差都写清「当前值 → 期望值」。**先读报告，再决定要不要动手。**

### 第 2 步 · 修复 🛠️

```bash
python scripts/fmt_apply.py "我的论文.docx" -o "论文-已规范化.docx" --report 变更日志.txt
```

- 默认**不覆盖原文件**，输出到新路径；输出路径等于原路径时会拒绝执行。
- 想先看看会改多少？加 `--dry-run`。
- 日志里会列出：分节/样式/段落/编号四类改动数量，以及**逐条**的编号剥离明细。
- 源稿标题写错了（比如一段挤了两条标题）？用 `--replace-file 替换表.txt` 显式改，脚本自己不做启发式瞎猜。

补充两个小开关：

```bash
--dry-run                  # 只统计，不写文件
--replace-file 替换表.txt  # 每行「原文<Tab>新文」，也可用 => 分隔
```

### 第 3 步 · 分节与页眉页脚 📑

```bash
python scripts/fmt_hf.py "论文-已规范化.docx" -o "论文-最终.docx" --title "论文题目"
```

| 节 | 内容 | 页眉 | 页脚页码 |
|---|---|---|---|
| 1 | 封面 | 无 | 无 |
| 2 | 摘要 / Abstract / 目录 / 声明 | 无 | 居中，大写罗马 I、II、III…… |
| 3 | 正文起（含参考文献、致谢） | 奇数页 = 当前章名；偶数页 = 论文题目 | 居中，阿拉伯，重新从 1 起 |

有些学校用**全校统一页眉**（比如「XX大学本科生毕业论文」），那就加 `--school-header`：

```bash
python scripts/fmt_hf.py "...docx" -o "...docx" --title "论文题目" --school-header "XX大学本科生毕业论文"
```

### 第 4 步 · 换学校（只在需要时才做）🏫

```bash
# 4a. 页眉校名
python scripts/fmt_hf.py "...docx" -o "...docx" --school-header "厦门大学本科生毕业论文"

# 4b. 封面校徽 / 校名图
python scripts/fmt_cover.py "...docx" -o "论文-交付.docx" \
       --logo "assets/xiamen-university-logo.png" --width-pt 300 --top-pt 28
```

### 第 5 步 · 复核 ✅

```bash
python scripts/fmt_check.py "论文-交付.docx"
```

期望：问题数归零，或只剩「已知局限」里那些需要人工判断的项。
**第六节的编号冲突数必须是 0。**

## ⚠️ 交付前必看

这几条是血泪教训，不是客套话。😤

1. **在 Word 里 `Ctrl+A` → `F9` 更新域**。目录、页码、页眉章名都是域，不刷新永远显示旧值（脚本已打开「打开时更新域」，但手动按一次更稳）。
2. **看 `fmt_apply` 日志的第二行**，正常长这样：
   ```
   封面/声明区保护：块 1..16 共 16 个块不套正文规范（自由排版）
   ```
   这行**没了**、或者范围大得离谱（比如 `1..300`），说明封面识别失手了 —— 停下来人工核对再继续。
3. **改完一定要用 Word 实际渲染一遍**再交付。编号重复、章标题折行这类问题在 XML 层面根本看不出来，光跑 `fmt_check` 会漏。
4. **页眉文字按你学校的规定来**。奇偶页不同（章名/题目）和全校统一页眉是两种流派，用 `--school-header` 切换，拿不准就各出一版对比。
5. **封面标题字号没变吧？** 源稿封面和正文同处一节时，识别可能失手把封面标题压成小四。

## 🗂️ 脚本一览

| 脚本 | 干什么 | 常用参数 |
|---|---|---|
| `scripts/fmt_check.py` | 只读诊断，六节报告 | `--json` 导出机器可读报告 · `--max-items` 控制明细条数 |
| `scripts/fmt_apply.py` | 执行修复，输出新文件 | `-o` · `--dry-run` · `--report` · `--replace-file` |
| `scripts/fmt_hf.py` | 分节 + 页码 + 页眉页脚 | `-o` · `--title` · `--school-header` · `--force` |
| `scripts/fmt_cover.py` | 换封面校徽 / 校名图 | `-o` · `--logo` · `--width-pt` · `--top-pt` · `--align` |
| `scripts/doc2docx.py` | `.doc` → `.docx`（调用本机 Word，无损） | `--overwrite` |
| `scripts/spec_rules.py` | **规范常量**（要改规范就改这里） | — |
| `scripts/docx_kit.py` | OOXML 工具库：样式继承链、角色识别、分节解析 | — |

**执行顺序很重要**：`fmt_check` → `fmt_apply` → `fmt_hf` → `fmt_cover` → `fmt_check`。
`fmt_hf` 必须在 `fmt_apply` 之后跑（它依赖已经套好的样式来定位章标题）。

## 🎯 规范基线（都写死在代码里，改一处即可）

| 项目 | 值 |
|---|---|
| 纸张 | A4（21.0 × 29.7 cm） |
| 正文边距 | 上 3.0 / 下 2.54 / 左 3.17 / 右 3.17 cm |
| 正文 | 宋体 · 小四(12pt) · 1.5 倍行距 · 首行缩进 2 字符 |
| 章标题 | 黑体 · 小三(15pt) · 加粗 · 居中 · 段前分页 |
| 节标题 | 黑体 · 四号(14pt) · 加粗 · 左对齐 |
| 小节标题 | 黑体 · 小四(12pt) · 加粗 |
| 篇级大标题 | 黑体 · 小二(18pt) · 加粗 · 居中（摘要/目录/参考文献/致谢） |
| 表格内文字 | 宋体 · 五号(10.5pt) · 居中 · 单倍行距 |
| 参考文献 | 宋体 · 五号 · 单倍行距 · 无首行缩进 · 编号 `[1]` 自动生成 |
| 图表注 | 宋体 · 六号(7.5pt) |
| 页眉 | 宋体 · 五号 · 居中 |
| 页脚 | 宋体 · 小五(9pt) · 居中 |

完整规范见 [`references/format-spec.md`](thesis-format-conformer/references/format-spec.md)。

> 规范来源是一份**实测的厦门大学硕士学位论文样例**，所有数值都是从它的 `styles.xml` / `document.xml` / `numbering.xml` 里抠出来的，不是拍脑袋写的。

## 🏫 想适配自己学校的模板？

规范数值集中在两个地方：`scripts/spec_rules.py` 和 `assets/reference-*.xml`。

1. 解压目标学校模板的 `.docx`，解析它的 `styles.xml` / `sectPr` / `numbering.xml`；
2. 用新模板的这两个文件替换 `assets/reference-styles.xml` 和 `reference-numbering.xml`；
3. 改 `spec_rules.py` 里的 `PAGE_*` / `MARGIN_*` / `STYLE_SPECS` / `ROLE_TO_STYLE`；
4. 拿模板自己跑一次 `fmt_check.py`，确认自检问题趋近于零，再投入使用。

**只换学校标识、规范不变**的话更简单：

```python
SCHOOL_NAME = "你的学校"                    # spec_rules.py
SCHOOL_HEADER_TEXT = "XX大学本科生毕业论文"
SCHOOL_COVER_LOGO = "assets/你的校徽.png"
```

或者运行时直接传 `--school-header` 和 `--logo`，代码都不用动。

## 🧠 设计立场（为什么它比"查找替换"靠谱）

它把 `.docx` 当成 **OOXML（zip 里的一堆 XML 部件）** 处理，而不是可见文本：

- **样式靠名字认，不靠 ID** —— `w:styleId` 是 Word 内部随机串（`a3`、`affff5` 这种），换个文档就变，一切匹配按 `w:name` 来。
- **格式算"有效值"** —— `docDefaults` → 样式继承链 → 段落直接格式，逐层覆盖后的结果才是它比对的对象。
- **分节符有两种落点** —— 段落 `pPr` 内嵌的 `sectPr` 和 `body` 末尾的 `sectPr`，都要认，否则多节文档会被当成单节。
- **编号不能当"多余格式"清掉** —— 章标题的「第X章」恰恰来自段落级 `numPr`，一刀切清除会让章标题彻底没编号。
- **标题里的手写编号必须剥离** —— 节及以下的编号挂在**样式**上，只删段落 `numPr` 根本挡不住，结果是「1.1 1.1 标题」。
- **写入 XML 要守元素顺序** —— `pPr` 的子元素、`sectPr` 里 `pgNumType` 的位置都有固定次序，顺序错了 Word 直接报文件损坏。

源码里到处是「实测踩过」的注释 —— 每一个坑都是拿真实文档压出来的。

## ⛔ 已知局限（这些得人工上）

1. **标题层级信息已丢失** —— 既没 heading 样式、文本也没「第X章 / 1.1」编号时，自动识别无从下手，只能对着目录人工比对。
2. **提纲式小标题会被自动提升** —— 像「`1` 金融监管的必要性」这种会被当成节标题，编号按章重排（原来各章从 1 起，重排后变 `2.1 / 2.2`）。改稿前先跑 `fmt_check` 看清单。
3. **一段挤了两条标题，只报不改** —— 比如「金融监管的必要性 银行业监管的必要性」。脚本不替你决定留哪条，用 `--replace-file` 自己改。
4. **封面/声明页的识别靠两条启发式** —— 极端排版下会失手（封面字样被长标题挤出前 400 字符，或短文档被整节判成封面）。自检方法见上文「交付前必看」第 2 条。
5. **表格内部不重排** —— 只规范表题和表格样式，单元格的合并、列宽不动，免得弄坏数据表。
6. **封面校名是纯文字时换不了** —— `fmt_cover.py` 处理的是**图片**形式的校徽/校名，文字版会报错退出，得人工换。
7. **域结果有缓存** —— 目录、页码、页眉章名改完必须 `F9` 刷新。
8. **源稿的空段落会被保留** —— 很多 `.doc` 靠空段落撑版面，套上规范后这些空段落会把前置部分摊成好几页空白。脚本不擅自删内容，你得自己决定怎么处理。

更多细节见 [`references/format-spec.md`](thesis-format-conformer/references/format-spec.md) 第 10 节。
