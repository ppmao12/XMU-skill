# 学位论文格式规范化

## 用途

将一份 `.docx` 论文的格式统一到既定的学位论文规范，或只做格式体检。规范基线为一份实测的厦门大学硕士学位论文样例（完整规范见 `references/format-spec.md`），规则以常量形式固化在 `scripts/spec_rules.py`。

核心能力：

1. **页面与分节** —— A4 纸张、规范页边距、文档网格、页码格式（封面无码 → 前置罗马数字 → 正文阿拉伯重新起 1）
2. **样式表** —— 按**样式名**（而非内部 styleId）把规范样式定义同步进目标文档，缺失则注入
3. **段落** —— 按语义角色（章/节/小节标题、图表题、参考文献……）套用规范样式，并清除与规范冲突的直接格式
4. **编号** —— 同步多级标题编号与参考文献编号定义；并把标题编号「归一」：
   剥离标题文本里的**手写编号**，改由自动编号生成（章标题挂段落级 `numPr`，
   节及以下靠样式级 `numPr`）。**不做这一步会渲染出「1.1 1.1 选题背景」式的重复编号。**
5. **分节与页眉页脚**（`fmt_hf.py`）—— 按「封面无码 → 前置罗马数字 → 正文阿拉伯重新起 1」
   重建三节，建立居中页码页脚与奇偶页页眉（奇数页 = 自动跟随章名的 `STYLEREF` 域，
   偶数页 = 论文题目），并打开文档的「奇偶页不同」与「打开时更新域」开关。
6. **学校品牌替换**（`fmt_cover.py`）—— 把封面上的校名 / 校徽图片换成指定学校的官方标志，
   版面（下方「本科毕业论文」字样、信息表）不动；页眉校名用 `fmt_hf.py --school-header`。
   规范学校名与标志文件记在 `spec_rules.SCHOOL_*`。
7. **源稿错标题的显式修正**（`fmt_apply.py --replace-file`）—— 源稿里常有一行挤了两条标题、
   或标题写错的情况。本 skill **不做启发式改写**，只在用户给出「原文 → 新文」对照表时按表改写；
   体检报告会先把可疑段落列出来供确认。

> **只支持 `.docx`（OOXML）**。Word 97-2003 的 `.doc` 须先用 Word 另存为 `.docx`
> （`Documents.Open` → `SaveAs2(FileFormat=16)`，实测无损保留分节、页眉页脚、表格），再交给本 skill。

## 何时使用

- 用户提供了一份论文章节 / 全文 `.docx`，要求"按学校格式规范调整""排版对齐范文"
- 用户想在不修改文件的前提下，得到一份格式偏差诊断报告
- 用户已完成写作，需要交付前的格式终检

**不适用**：从零撰写论文内容（那是写作任务）；仅调整单个表格或某一段的样式（那属于定点编辑）。

## 工作流

按「体检 → 修复 → 复核」三步执行，**不要跳过第一步**。

### 第 1 步：体检（只读，不改文件）

```bash
python scripts/fmt_check.py "<论文.docx>" --json "<报告.json>"
```

输出六节报告：页面与分节、样式表、段落角色分布、段落格式偏差明细、页眉页脚、**标题编号冲突**。

先读报告，判断问题规模与类型，再决定修复策略。报告中的每一处偏差都给出了「当前值 → 期望值」。

> 若**第三节**的 `section_title` 数量明显多于文档里「N.M」式标题的个数，说明命中了提纲式小标题
> （见「已知局限 ②」）—— 改稿前应把这些段落的文本挑出来给用户过目。

### 第 2 步：修复

```bash
python scripts/fmt_apply.py "<论文.docx>" -o "<论文-已规范化.docx>" --report "<变更日志.txt>"
```

- **默认不覆盖原文件**，输出到新路径；若输出路径与原路径相同会拒绝执行。
- 先用 `--dry-run` 预览改动统计而不写文件。
- 变更日志给出：分节/样式/段落/编号四类改动数量与角色分布，以及**标题编号归一的逐条明细**
  （哪一段剥离了哪个编号前缀、剩下了什么文本），可用于向用户交代改了什么。
- **先看第二行「封面/声明区保护」**：正常应形如
  `封面/声明区保护：块 1..16 共 16 个块不套正文规范（自由排版）`。
  若这行**没有**，说明源稿里没识别出封面 —— 大概率是「封面 + 正文同节」且封面字样超出开头 400 字符，
  封面标题会被当正文改写。若保护范围**明显过大**（例如 1..300），说明整节被误判为封面，
  所有段落都会漏做 —— 这两种情况都要先人工核对再继续（见「已知局限 ④」）。
- `--replace-file <表.txt>` 显式修正源稿错标题：每行「原文<Tab>新文」（`#` 注释，亦可用 `=>` 分隔）。
  匹配忽略空白差异、也忽略段首编号，因此不必写「1 」「2.1 」。**未命中的条目会写进日志**，
  防止表里写了却没生效。
  > 顺序很关键：脚本**先按原文判定段落角色、再改写文本**。源稿的提纲小标题是靠「1 xxx」这类
  > 段首编号识别的，若先替换（新标题不带编号）再判角色，该段会被降级成正文（实测踩过）。

### 第 3 步：分节与页眉页脚

```bash
python scripts/fmt_hf.py "<论文-已规范化.docx>" -o "<论文-最终.docx>" --title "论文题目"
```

把文档重建成三段式分节，并建立页码页脚与奇偶页页眉：

| 节 | 内容 | 页眉 | 页脚页码 |
|---|---|---|---|
| 1 | 封面 | 无 | 无 |
| 2 | 摘要 / Abstract / 目录 / 声明 | 无 | 居中，大写罗马 I、II、III…… |
| 3 | 正文起（含参考文献、致谢） | 奇数页 = `STYLEREF` 当前章名；偶数页 = 论文题目 | 居中，阿拉伯，重新从 1 起 |

- 节的边界由文档自身内容定位（第一个「摘要/Abstract/目录/声明」标题、第一个章标题），
  不依赖段落号；找不到会报错退出，不会乱切。
- `--school-header "XX大学本科生毕业论文"` 可改为「全校统一页眉」，奇偶页相同
  （不少学校用这一种，比奇偶页不同更简单）。
- 文档已有页眉页脚部件时会拒绝执行（防重复新增），确认要重建加 `--force`。
- **奇偶页页脚必须 default 与 even 同时挂**，否则偶数页会没有页码（实测踩过）。

### 第 4 步：学校品牌（换学校时才做）

```bash
# 4a. 页眉校名（整页统一的那一种）
python scripts/fmt_hf.py "<论文-已规范化.docx>" -o "<论文-最终.docx>" \
       --school-header "厦门大学本科生毕业论文"

# 4b. 封面标志：封面左上角换成目标学校的官方 logo
python scripts/fmt_cover.py "<论文-最终.docx>" -o "<论文-交付.docx>" \
       --logo "assets/xiamen-university-logo.png" --width-pt 300 --top-pt 28
```

`fmt_cover.py` 的做法与边界：

- **封面图区** = 文档开头、第一段有正文的段落之前，所有含图片的段落。
- 只保留**第一张**图（通常占位最宽，即校名那一条），把它的位图换成新标志，并按新标志的
  宽高比重算 `width`/`height`（避免拉伸），水平居中于版心；**其余封面图整段删除**。
- 位图按原扩展名编码（png→png、jpeg→jpeg），因此 `[Content_Types].xml` 无需改动，
  也不会污染其它章节的图。
- 尺寸写在 VML 的 `style` 里、以 pt 计，Word 按 pt 缩放，**无需重采样位图**（保持原始清晰度）。
- 同时支持 VML（`w:pict`/`v:shape`）与 DrawingML（`w:drawing`/`wp:extent`）两种承载方式。
- 封面若本来就没有校徽图（例如校名是纯文字），本脚本会报错退出，须人工处理。

换一所学校时改三处即可：`spec_rules.SCHOOL_NAME` / `SCHOOL_HEADER_TEXT` / `SCHOOL_COVER_LOGO`，
或直接传 `--school-header` 与 `--logo`。

### 第 5 步：复核

```bash
python scripts/fmt_check.py "<论文-交付.docx>"
```

期望结果：问题数归零或仅剩「已知局限」所列的人工项。若仍有大量段落偏差，检查是否命中了局限 ①（标题层级信息丢失）。

**第六节的编号冲突数应当为 0** —— 若不为 0，说明还有标题文本带着手写编号，须人工处理（脚本只处理识别出来的标题角色）。

### 交付时要提醒用户

1. 在 Word 中打开产出文件后，**全选 → 按 F9 更新域**，目录、页码与页眉章名才会刷新
   （域结果是缓存值；`fmt_hf` 已打开「打开时更新域」，但手动 F9 更保险）。
2. 封面、原创性声明页属自由排版区：脚本会自动识别并**跳过**（不套正文样式、用封面页边距），
   但**不改其文字与版面**，仍须对照学校模板人工核对。
   交付前请确认封面标题字号未被改动 —— 若源稿封面与正文同处一节且识别失手，
   封面标题会被按正文字号压小（见「已知局限 ④」）。
3. **页眉文字要按学校确认**：奇偶页不同（章名 / 论文题目）与全校统一页眉
   （如「XX大学本科生毕业论文」）是两种常见做法，用 `--school-header` 切换。
   两者可各出一版让用户挑，但**要与范文对齐的那一版**通常是奇偶页不同（范文页眉不含校名）。
4. **源稿的空段落会被完整保留**：很多 `.doc` 稿用空段落撑版面，套规范后这些空段落会把前置部分
   摊成多处空白页。这属内容问题、脚本不擅自删除，但**要主动告知用户**并给出两种可选处理
   （删冗余空段，或改为在篇级标题上设「段前分页」）。
5. 原文档若**没有**「摘要/Abstract/目录」这类前置标题，`fmt_hf` 会拒绝分节 ——
   这是有意的：宁可停下让人确认，也不要凭段落号乱切。
6. 改稿后**用 Word 实际渲染一次**再交付。编号、域这类问题在 XML 层面不可见，
   只看 `fmt_check` 会漏（本节几条"实测踩过"的坑，都是靠 Word 渲染才发现的）：
   ```python
   # 读标题的自动编号与文本，判断是否重复编号
   p.Range.ListFormat.ListString     # 自动编号，如 '1.1'
   p.Range.Text                      # 段落文本
   # 读各节页眉页脚的实际渲染文本（含域结果）
   doc.Sections(i).Headers(1).Range.Text    # 1=奇数页(默认) 2=首页 3=偶数页
   doc.Sections(i).Footers(1).Range.Text
   ```

## 脚本说明

| 脚本 | 作用 | 关键参数 |
|---|---|---|
| `scripts/doc2docx.py` | 把 `.doc` 另存为 `.docx`（调用本机 Word，非格式解析，无损） | `--overwrite` 允许覆盖输出 |
| `scripts/spec_rules.py` | 规范常量（页面、样式、角色映射、编号冲突判据）。**修改规范只需改这里** | — |
| `scripts/docx_kit.py` | OOXML 工具库：样式继承链、有效格式、**段落角色识别**、分节解析、**块级节类型判型**（`block_kinds` / `leading_front_end` / `section_kind`）、`para_text`/`strip_prefix_chars`（行内文本遍历） | — |
| `scripts/fmt_check.py` | 只读诊断（六节报告） | `--json` 导出机器可读报告；`--max-items` 控制明细条数 |
| `scripts/fmt_apply.py` | 执行修复，输出新文件 | `-o` 输出路径；`--dry-run` 只统计；`--report` 写日志；`--replace-file` 显式文本替换表 |
| `scripts/fmt_hf.py` | 分节 + 页码 + 页眉页脚（在 `fmt_apply` 之后跑） | `-o` 输出路径；`--title` 论文题目；`--school-header` 改统一页眉；`--force` 强制重建 |
| `scripts/fmt_cover.py` | 封面校徽 / 校名图换成指定学校的标志（在 `fmt_hf` 之后跑） | `-o` 输出；`--logo` 新标志；`--width-pt` / `--top-pt` / `--align` |

`fmt_apply.py` 内部三步：`sync_styles()`（样式）→ `sync_numbering()`（编号定义）
→ `normalize_heading_number()`（逐段剥离手写编号、按层级挂 `numPr`，章标题补 `ind left=0`）。

**资产**：`assets/reference-styles.xml`（规范样式库）、`assets/reference-numbering.xml`（规范编号库）、
`assets/xiamen-university-logo.png`（封面用官方标志）。`fmt_apply.py` 以样式/编号库为来源，
因此规范的调整应以更新这两个文件 + `spec_rules.py` 为准。

## 技术立场

把 `.docx` 当作 **OOXML（zip 内 XML 部件）** 处理，而不是可见文本：

- 样式 ID（`w:styleId`）是 Word 内部随机串（如 `a3`、`affff5`），**跨文档不可移植**；一切匹配按样式名 `w:name` 进行。
- 段落有效格式 = `docDefaults` → 样式继承链（`basedOn`）→ 段落直接格式，逐层覆盖。体检报告比较的就是这个合并结果。
- 分节符有两种落点：段落 `pPr` 内嵌 `sectPr` 与 `body` 末的 `sectPr`，两者都要识别，否则多节文档会被误判为单节。
- 页眉页脚未定义时**继承上一节**，这是 OOXML 规则，不是缺陷。
- 写入 XML 时须遵守元素顺序（`pPr` 子元素有固定次序），否则 Word 会报文件损坏。
- **编号不能当"多余直接格式"清掉**：章标题的「第X章」恰恰来自段落级 `numPr`，
  一刀切清除会让章标题彻底失去编号（实测踩过），故 `numPr` 不在 `CLEAR_PPR` 内。
- **标题文本里的手写编号必须剥离**：节及以下的编号挂在**样式**上，只删段落 `numPr` 挡不住它，
  结果是「1.1 1.1 标题」。改稿前后都该看 `fmt_check` 第六节的冲突计数。
- **`para_text()` 只把 run 内的 `w:tab`/`w:br` 当文本**：`w:pPr/w:tabs` 里的是**制表位定义**，
  若一并计入，段首会凭空多出一个字符，让所有按字符数定位的偏移量整体错位（实测踩过）。
- **新建分节靠「段落内嵌 `sectPr`」**：某段 `pPr` 里的 `sectPr` 描述的是「到此为止」这一节的属性，
  且必须是 `pPr` 的最后一个子元素（`pPrChange` 之前）。`pgNumType` 的位置也有讲究 ——
  在 `pgMar` 之后、`cols`/`docGrid` 之前。顺序错了 Word 会报文件损坏。
- **打开 `evenAndOddHeaders` 后，偶数页只认 `even` 类型的页眉页脚引用**：
  页脚若只挂 `default`，偶数页就会没有页码（实测踩过）。同一部件可被 `default` 与 `even` 同时引用。
- **`w:updateFields`** 让 Word 打开时自动重算域，避免页眉章名/页码停留在缓存值。
- **章标题必须写 `w:ind w:left="0"`**：多级编号的 `ilvl=0` 定义自带 `ind left=4819 firstLine=0`
  （≈8.5 cm），范文靠段落级 `w:ind left="0"` 把它抵消。缺这一项，章标题会被推到页面右侧，
  长标题（如「综合监管目的和银行风险」）当场折行、并暴露出编号的悬挂缩进（实测踩过）。
- **剥离编号后要清空 run**：删掉「1.1 」「第二章 」后，原 run 会留下空 `<w:t/>`。空文本不渲染
  （Word 的 `Range.Text` 也读不到），但部分编辑器在「显示编辑标记」下会把空段落画成小方块，
  容易被当成文档里的乱码。`normalize_heading_number()` 会顺手清理。
- **编辑器里看到的「乱码」不一定是真的**：交付前若用户截图里有可疑符号（小方块、「'」等），
  先用 Word COM 读 `Range.Text`/`Range.ListFormat.ListString` 核对，再决定是否真有问题 ——
  那些多半是「显示编辑标记」（Word/WPS 的 `Ctrl+Shift+8`）画出来的段落/制表/空段落符号，
  不会出现在 PDF 或打印稿里。
- **封面/声明页的判型必须做到「块级」，不能只做「节级」**：源稿（尤其 `.doc` 转换来的）
  经常**整篇只有 1 个 `sectPr`**，封面与正文同节。此时若按整节文本判型，节里既有封面字样
  （学号/指导教师）又有整篇正文，整节会被判成封面 → **所有段落一律跳过规范化**
  （实测 109 个段落全部漏做），封面标题也会被顺带改写（「本科毕业论文」初号 42pt → 小四 12pt）。
  现行做法两步合并（`docx_kit.block_kinds`）：
  1. **节级判型**，并加一道闸 —— 本节文本若已含章标题、或长度 ≥1200 字符，一律按正文处理
     （`_looks_like_body`），防止整节被封面字样带走；
  2. **位置兜底** —— 再按位置从文档开头扫出「前置区」（遇第一个章标题或
     摘要/Abstract/目录/声明/参考文献即停，`leading_front_end`），若该区本身就像封面/声明页，
     就把区内的块改判。**只做「升级」，从不把已判为 cover/declaration 的块改回正文。**
  判型只看文本开头的 400 字符（封面字样只会出现在开头），避免正文里偶现的
  「研究方向」「学术不端」把整节带走。
- **封面信息常放在表格里**：封面的「学校编码 / 学号 / 作者姓名 / 指导教师」几乎都在封面信息表中，
  判型用的 `range_text()` 因此必须把**表格单元格**的文字也算上，只看段落文本会把封面误判为正文。

## 已知局限

详见 `references/format-spec.md` 第 10 节。最需要留意的前两条：

> **① 若文档的标题既没有 heading 样式、文本也没有"第X章 / 1.1"编号**（编号原为自动生成，后被转成纯文本或删除），自动识别无法复原层级。此时不要强行批量套样式，应改为依据目录（TOC）中的标题文本人工比对，或请用户确认标题清单。

> **② 提纲式小标题会被自动提升。** 形如 `1 金融监管的必要性`、`2 面临的风险` 的段落在识别时会被当作节标题。规则限定了「1-2 位数字 + 空白 + 全文 ≤40 字 + 无句末标点」，误判率低；但命中后编号会由自动编号按章重排（原文各章内部重新从 1 起，重排后变为 `2.1 / 2.2 / …`）。**改稿前应先跑 `fmt_check` 看清单，并与用户确认是否接受重排。**

> **③ 一段里挤了两条标题，脚本只报不改。** 如「金融监管的必要性 银行业监管的必要性」（作者把两条提纲并到一行、或删改标题时漏删）。`fmt_check` 第六节会以「疑似一段里挤了两条标题」列出，但**不会替你选哪一条**——须核对作者的其他版本/目录后，用 `--replace-file` 显式改写。判据限定「章/节级 + 空白分隔 + 两侧各 ≥5 个非空白字符」，因此「摘  要」「第三章 研究方法」不会被误报。

> **④ 封面/声明页的识别依赖两条启发式，极端排版下会失手。** 判型要求封面字样出现在
> 该节**开头 400 字符**以内；若封面把长论文题目排在学号/指导教师之前、把这些字样挤到 400 字符之后，
> 可能识别不到（此时封面会被当正文改写，表现为封面标题字号变小）。反之，若某节既有封面又有正文
> 且**文本不足 1200 字符、又没有章标题**（例如只有封面 + 摘要的短文档），位置兜底会把整节判成封面。
> 两种情形都会在 `fmt_apply` 的日志里留下痕迹 —— 正常应打印
> 「封面/声明区保护：块 a..b 共 n 个块」，**若该行缺失、或保护范围明显过大，先人工核对再交付**。

## 扩展其他学校规范

本 skill 的规范数值集中在 `spec_rules.py` 与 `assets/reference-*.xml`。适配另一所学校的模板时：

1. 解压目标模板的 `.docx`，用 `scripts/docx_kit.py` 的方式解析其 `styles.xml` / `sectPr` / `numbering.xml`；
2. 用新模板的 `styles.xml`、`numbering.xml` 替换 `assets/` 下同名文件；
3. 更新 `spec_rules.py` 中的 `PAGE_*` / `MARGIN_*` / `STYLE_SPECS` / `ROLE_TO_STYLE`；
4. 用该模板自身跑一次 `fmt_check.py`，确认自检问题趋近于零（说明规则与模板一致），再投放使用。

**只换学校标识（规范不变）**：改 `spec_rules.SCHOOL_NAME` / `SCHOOL_HEADER_TEXT` /
`SCHOOL_COVER_LOGO`，或运行时传 `--school-header` 与 `--logo`；封面标志图片放进 `assets/`。
